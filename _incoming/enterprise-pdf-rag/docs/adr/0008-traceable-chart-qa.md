# ADR 0008 — Admit only source-qualified percentage facts to ChartQA

Status: Accepted for the first traceable numeric ChartQA slice, 2026-09-19.

## Context

The physical-pages-1–20 run has durable source SVGs, inferred ChartIR and independent descriptions for all 29 chart objects. Nine charts currently expose source-label-only retrieval projections, while no numerical relationship is qualified. The existing label retrieval snapshot therefore cannot answer financial questions. Agreement between the two model branches, model confidence, a readable label, colour, proximity or a whole-chart bounding box cannot promote a number into trusted evidence.

The approved PRD requires answer precision, answer coverage, refusal rate and citation correctness together. A system that refuses every question is not a business pass. P1 through P4 and the full P5 milestone remain partially implemented: the representative gold set, complex table gates, distributed ingestion controls, all retrieval types, TableQA, permissions and broad figure validation are still incomplete. This slice cannot be used to claim that those milestones, all 29 charts or general financial QA have passed.

## Decision

The first numeric ChartQA scope is a source-qualified donut chart with explicit percentage labels. Admission requires an independent qualification receipt that binds the pinned source revision, physical page and region, the exact native and cropped SVG identities, the complete raw ChartIR and description branches, and each approved series, category, period, unit and value occurrence to source evidence and reviewed chart geometry. A model output cannot certify itself. The existing source-label-only projection and snapshot are not upgraded in place; numerical qualification creates new immutable artifacts and a new snapshot.

Because the source PDF renders text as paths, the old text sidecar alone cannot prove that every neutral paint operation is a glyph rather than an occluder. The admission proof must replay the same source page through pdfspine's device interface and preserve Unicode, glyph ID, text rendering matrix, fill and alpha, rendering mode and embedded font bytes. It then matches the embedded-font glyph outline to the native SVG path and accounts for the complete paint sequence. The trace and proof are content-addressed and bind the original PDF digest, page and native SVG plus the proof producer version. Missing glyph provenance, an unmatched or unsupported paint, a colour or geometry heuristic, or a font-name-only match leaves the relationship unqualified. This mechanical proof is neither a human approval signature nor model self-verification.

The source-backed query API accepts a pinned `processing_id`, `snapshot_id` and `member_id`, an operation, a series, a period, the literal input unit `%`, and one or two requested points identified by point ID and category. This describes the fixed local evidence slice; it does not imply that multi-tenant authorization or the full production release gates exist. The supported operations are:

- `lookup`, with exactly one explicit percentage point;
- `percentage_point_difference`, with exactly two points from the same figure, metric and period, subtracted in request order.

The caller cannot submit a value or a verification flag. Currency, date-range interpretation, inferred operating definitions, ratios, estimated values, unlabeled marks and other chart grammars are outside this slice. Unknown categories, series, periods or units; estimated or unavailable values; a missing branch; and a wrong source, member or snapshot must fail closed. A normal evidence-based refusal is an `abstained` business result. Pin conflicts and unavailable immutable dependencies remain transport errors and are separately measured.

An answered lookup returns its canonical decimal as a string, the input unit `%`, value kind, source display text and the input claim. A derived percentage-point difference returns a canonical decimal string, the output unit `percentage_points`, an explicit derived value kind, no fabricated source display string, both ordered operand claims and an independent calculation receipt. Decimal arithmetic uses precision 64 with `ROUND_HALF_EVEN`, traps `Inexact` and `Rounded`, accepts at most 28 input decimal places, and never silently rounds a result. The receipt records the ordered input field references and values as well as the output, so an accidentally equal result from wrong operands cannot pass. Every accepted field and operand has a field-level citation through ChartIR field, SVG element or source occurrence, PDF revision, physical page and top-left bounding box. A whole-object citation is insufficient. When no real FigureBundle exists, the response uses the actual immutable member closure and does not invent a bundle ID.

The golden set is independent of the model branches. Reviewers establish facts from the stored native SVG, source text sidecar and rendered source region, recording exact occurrence IDs, text, bounding boxes and content digests. LLM ChartIR and descriptions can identify candidates for review but are never the gold authority. The initial positive facts are limited to the reviewed page-18 Distribution Mix donut: VONB in 1H26, Agency 72% and Partnerships 28%. All other facts remain unsupported until independently reviewed under a versioned qualification method.

The offline evaluator consumes captured structured query outcomes; it does not call a model or service. It validates exact decimal, comparator/sign, unit, value kind, source display and field citations, as well as the pinned processing/snapshot/member identities. The report is deterministic and content-addressable. It reports at least answer precision, positive answer coverage, refusal rate, refusal recall on unanswerable cases, over-refusal on answerable cases, citation exactness and coverage, hard-negative escape rate, and transport-error count. Metrics are stratified by positive, hard-negative and unsupported cases.

For this narrow frozen scope, required thresholds are 100% answer precision, 100% positive answer coverage, 100% field citation exactness and coverage, and zero hard-negative escapes. The evaluator fails if thresholds are missing, if the gold set has no positive case, or if positive answer coverage is zero. Unsupported-scope refusal is reported separately. Passing this slice does not establish a ranking benchmark or coverage outside the reviewed donut.

## Validation

Freeze a source-bound golden fixture with positive lookups, ordered percentage-point differences, wrong series/category/period/unit, estimated and unknown values, missing-branch and wrong-source/snapshot cases, plus unsupported grammar and financial-unit examples. Source artifact mutations are exercised through an isolated copy of the real resolver store: invalid evidence is a transport rejection, while domain-only fixtures separately test the finer unsupported-value and grammar refusals. A mutation must be checked against the gold so that a hard negative is not accidentally another true fact.

Use offline tests to prove that correct answers and citations pass; a wrong number, sign, operand order, source occurrence, bounding box, page, member or snapshot fails; an all-abstain result fails positive coverage; and expected refusals do not inflate answer precision. Run the project formatting and complete offline gate after the production implementation and evaluator are integrated. No test in this slice makes a model or network call.
